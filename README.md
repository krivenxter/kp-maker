# Calltouch Proposal Maker

Внутренний React-инструмент для сборки персонализированных коммерческих предложений Calltouch. Презентация строится детерминированно из `ProposalDocument`: форма → нормализация → Zod-валидация → выбор layout → PptxGenJS → редактируемый PPTX.

## Запуск

Требования: Node.js 20+ и pnpm.

```bash
pnpm install
pnpm dev
```

Откройте `http://localhost:5173`.

Проверки:

```bash
pnpm test
pnpm build
```

## Возможности

- мастер из 4 шагов с фиксированной навигацией и превью тех же сцен, что попадают в экспорт;
- данные клиента, отрасль, сайт, выбор бренд-профиля и обложки;
- менеджер из справочника или своё контактное лицо: имя, фамилия, должность, почта, телефон и фотография;
- каталог из 35 продуктов с фирменными 3D-визуалами, поиском и фильтрацией;
- 1–5 продуктов и 1–3 релевантных кейса; рабочая библиотека содержит 30 подтверждённых кейсов с логотипами, источниками и 1–3 метриками, а у ручного кейса можно задать от 1 до 3 метрик и необязательную ссылку;
- 1–3 тарифных плана с адаптивной компоновкой, категории ПО/связь/другое, ежемесячные и разовые платежи, полная цена и скидка;
- автоматический расчёт итогов, включая `firstMonthTotal` и `nextMonthsTotal`;
- автосохранение даже незавершённого черновика в localStorage: данные записываются при изменениях, сворачивании вкладки и уходе со страницы;
- импорт и экспорт валидного `ProposalDocument` в JSON через меню «Черновик» в шапке;
- понятная проверка обязательных полей: предупреждения показываются у конкретного поля и в общей сводке без внутренних кодов схемы;
- переключатель стиля презентации «Тёмная / Светлая» в настройках обложки: тема сохраняется в `ProposalDocument` и применяется к превью, PPTX, PDF и One-pager;
- светлая тема с отдельными ассетами `backgrounds-light`, тёмным логотипом Calltouch, тёмными логотипами кейсов и контрастной палитрой без светлого текста на светлом фоне;
- фиксированная панель экспорта на последнем шаге с выбором полного КП, One-pager или обоих вариантов;
- единое правило контраста: на насыщенных циановых кнопках и плашках используется белый текст и белые check-иконки; это правило одинаково работает в интерфейсе, HTML-превью, PPTX и PDF;
- редактируемый PPTX с кликабельными ссылками, сохранёнными пропорциями изображений и встроенными шрифтами;
- PDF-экспорт через LibreOffice с индикатором доступности сервиса: PDF строится из готового PPTX, а не из скриншотов;
- генератор PPTX загружается только при экспорте и не утяжеляет первоначальное открытие формы.

## Стили презентации

Переключатель находится на шаге 1, в блоке «Обложка КП». По умолчанию используется тёмная тема, поэтому старые черновики продолжают выглядеть как раньше. Выбранная тема записывается в поле `presentationTheme` со значениями `dark` или `light`.

Тема влияет на все экспортные поверхности:

- полное КП: обложка, контентные слайды, слайд кейсов и финальный слайд;
- One-pager: фон, карточки, текст, контактный блок и логотип релевантного кейса;
- HTML-превью: сцены собираются теми же renderer-ами, что и PPTX;
- PDF: LibreOffice конвертирует тот же редактируемый PPTX, поэтому в PDF сохраняется текстовый слой.

В светлой теме для обложки и финального слайда используются PNG-фоны из `calltouch-assets/backgrounds-light`. Контентные слайды используют белую или светло-серо-голубую поверхность, тёмный основной текст и циановый акцент. Для логотипов кейсов предусмотрен отдельный набор `calltouch-assets/case-logos-dark`. One-pager в светлой теме не получает тёмную подложку: его карточки только немного темнее основного фона.

## Форматы КП

Из одной и той же сущности `ProposalDocument` можно скачать:

- **Полное КП** — 7-слайдовая презентация;
- **One-pager** — самостоятельное однослайдовое КП 16:9;
- **Оба варианта** — два отдельных PPTX и, при запущенном PDF-адаптере, два PDF.

One-pager не копирует полную презентацию: в нём остаются до 4 продуктов, до 3 benefits, один наиболее релевантный кейс, компактные условия, менеджер и короткая юридическая формулировка. Layout выбирается детерминированно: `onepager_standard`, `onepager_discount` или `onepager_compare` (для двух вариантов тарифа). Если данные не помещаются по лимитам, экспорт One-pager блокируется с понятным предупреждением — текст не уменьшается бесконтрольно. One-pager использует ту же выбранную тему, что и полное КП.

Во время подготовки файла кнопка экспорта показывает состояние рендера и ориентир по времени. PPTX обычно собирается за несколько секунд, PDF может занимать до 20 секунд, потому что после генерации PPTX проходит отдельную конвертацию через LibreOffice. Повторное нажатие во время рендера заблокировано, чтобы не создавать дубликаты запросов.

## PDF

PPTX остаётся source of truth. PDF создаётся конвертацией готового PPTX через LibreOffice headless — слайды не рендерятся в изображения, поэтому текст и ссылки остаются настоящими объектами PDF. Для локальной разработки требуется установленный LibreOffice. Обычная команда разработки запускает интерфейс и PDF-адаптер вместе:

```bash
pnpm dev
```

На Windows приложение автоматически проверяет стандартный путь установки LibreOffice. Порт и нестандартный путь задаются через environment variables, см. `.env.example`. Frontend проверяет `GET /api/export/pdf/health`, а затем отправляет готовый PPTX в `POST /api/export/pdf`; сервер использует изолированный временный профиль LibreOffice и удаляет рабочую директорию после ответа.

В PDF-сервисе используются те же Dela Gothic One, Unbounded и Museo Sans Cyrl, что и при генерации PPTX. Логотипы Calltouch предварительно растеризуются в PNG высокого разрешения, а отсутствующие тёмные логотипы кейсов заменяются локально тонированной версией — это предотвращает тонкие/неверные начертания и размытые шапки после конвертации.

В PPTX шрифты встраиваются автоматически. Дополнительная кнопка «Aa Шрифты» в панели экспорта скачивает файлы Museo Sans Cyrl и Dela Gothic One для редактирования презентации на другом компьютере. Встраивание не гарантирует одинаковую замену шрифтов в уже установленной версии PowerPoint, поэтому для ручного редактирования рекомендуется установить скачанный комплект.

Для Vercel нужно развернуть отдельный Docker-сервис из [`deploy/pdf-service/Dockerfile`](deploy/pdf-service/Dockerfile), а в настройках Vercel указать `VITE_PDF_API_URL` с его публичным URL. Полная инструкция находится в [`deploy/pdf-service/README.md`](deploy/pdf-service/README.md).

Для отдельного запуска только интерфейса или только PDF-адаптера остаются команды `pnpm dev:web` и `pnpm server`.

## Архитектура

- `src/schemas` — контракты Proposal и pricing;
- `src/data` — утверждённые admin-справочники;
- `src/domain` — расчёты и выбор cases/layout/flow, а также правила One-pager;
- `src/presentation` — общие tokens, палитры тем, helpers, 7 PptxGenJS-renderers полного КП, renderer One-pager и общий preview recorder;
- `src/components/preview` — HTML preview на той же semantic model;
- `src/components/export` — сводка ошибок и фиксированная панель экспорта;
- `src/drafts` — сохранение, восстановление и миграция незавершённых черновиков;
- `src/export` — скачивание PPTX и обращение к локальному PDF-адаптеру;
- `server` — локальный PDF adapter, запускаемый вместе с Vite.

Шрифты подключены локально и встраиваются в PPTX: для EXLANTIX используются Unbounded + Museo Sans Cyrl, для нейтрального профиля — Dela Gothic One + Museo Sans Cyrl. Museo Sans Cyrl 300 используется для обычного текста, 700 — для акцентов и элементов интерфейса. Профиль body-шрифта переключается одной константой `ACTIVE_BODY_FONT` в `src/presentation/design/tokens.ts`; прежний профиль Manrope сохранён для быстрого отката. Для стабильной конвертации LibreOffice используются локальные OTF-версии Museo и статические файлы Unbounded. В интерфейсе и презентациях используются пять семантических типографических ролей: display, title, heading, body и caption. Текст остаётся редактируемым.

## Данные и ограничения

Продуктовые факты, готовые кейсы, сценарии и юридические формулировки берутся только из приложенных Calltouch-референсов и локальных справочников: `products.json`, `cases.json`, `solutionFlows.json`, `managers.json` и `legalTerms.json`. Автоматический подбор использует только утверждённые метрики справочника; достоверность метрик добавленного вручную кейса подтверждает пользователь. Секреты не хранятся в source code и не попадают во frontend bundle.

Кейсы из `materials/Calltouch All Products.pptx` проходят строгую схему `src/schemas/caseLibrary.ts`. Подтверждённые записи находятся в `src/data/cases.json`; спорные записи с несовпадающими ссылками или цифрами изолированы в `src/data/caseCandidatesNeedsReview.json` и не участвуют в автоматическом подборе. История текущего импорта описана в [`docs/CASE_IMPORT_AUDIT.md`](docs/CASE_IMPORT_AUDIT.md).

Рекомендуемая структура и правила пополнения контентной базы описаны в [`docs/CONTENT_LIBRARY.md`](docs/CONTENT_LIBRARY.md).

## Совместимость черновиков

Актуальная схема документа — `version: 1`. При загрузке старого черновика ручные кейсы с одиночным полем `metric` автоматически преобразуются в массив `metrics`; устаревшие служебные поля удаляются. Новые документы поддерживают от одной до трёх метрик на кейс.

Автоматическое восстановление намеренно не требует, чтобы незавершённая форма уже проходила финальную проверку: введённые значения не теряются после перезагрузки. Ручной импорт JSON остаётся строгим и не применяет повреждённый документ.

Фотография своего менеджера обрезается до квадрата 512×512, сохраняется в черновике как Data URL и ограничена схемой размером 800 КБ.
